# 🍃 MongoDB সংস্করণ (পরীক্ষামূলক)

মালিকের সিদ্ধান্ত (২০২৬-১০-২৩): লাইভ দোকান এখন যেমন আছে, PostgreSQL (Supabase) দিয়েই চলবে। পাশে
`mongodb` শাখায় ধাপে ধাপে MongoDB দিয়ে চলার মতো সংস্করণ তৈরি হবে। এটা লাইভ সাইটের সাথে যুক্ত নয়।
পরে পেইড হোস্টিংয়ে যাওয়ার সময় সুইচ করা হবে।

## ধাপ ১ — ডাটা হুবহু MongoDB-তে (তৈরি)
- `schema.ts`: `lib/db.ts` থেকে প্রতিটা টেবিল → collection। একক primary key → `_id`। টাকা/numeric →
  Decimal128 (পয়সা পর্যন্ত নিখুঁত), সময় → date, ছবি → binary। সব unique নিয়ম (শর্তসাপেক্ষ ও
  বড়-ছোট-হাতের-অক্ষর-নিরপেক্ষগুলোসহ) → MongoDB index।
- `convert.ts`: দোকানের নিজের ব্যাকআপ ফাইল → প্রতিটা collection-এর জন্য একটা Extended JSON ফাইল,
  সাথে `_plan.json` (index, id counter, যা হুবহু নেওয়া যায়নি)।
  `npx tsx tools/mongo/convert.ts <backup.smbk> <folder> --password=…`
- `load.ts`: ফোল্ডারটা যেকোনো MongoDB-তে (Atlas বা নিজের সার্ভার) বসায়।
  `MONGODB_URI=… npx tsx tools/mongo/load.ts <folder> --fresh`
- `verify.ts`: PostgreSQL আর MongoDB মিলিয়ে দেখে: সারির সংখ্যা, প্রতিটা টাকার কলামের যোগফল আর
  প্রথম সারিগুলোর প্রতিটা ঘর।
- `.github/workflows/mongodb.yml`: `mongodb` শাখায় প্রতিটা push-এ এই পুরো পথটা একটা টেস্ট দোকান দিয়ে চালায়।

## পরের ধাপ — সাইটের কোড MongoDB-তে (বাকি)
সাইটের প্রায় ৫৭০টা SQL কোয়েরি অংশ অংশ করে MongoDB-র জন্য লিখতে হবে। একই টেস্ট দোকানে দুই সংস্করণ
চালিয়ে parity যন্ত্র দিয়ে ~৫৮০টা পেজ আর সব কাজ মিলিয়ে দেখা হবে।
1. ডাটাবেসের ভিত (`lib/db.ts`, `lib/pg.ts` → MongoDB সংযোগ, transaction, counter দিয়ে id)।
2. পণ্য, ক্যাটাগরি, ব্র্যান্ড, ছবি (দোকানের পেজগুলো)।
3. অর্ডার, স্টক, কুপন, কাস্টমার (চেকআউট — সবচেয়ে সাবধানে)।
4. পারচেজ, সাপ্লায়ার, হিসাব, রিপোর্ট, প্যাকিং।
5. বাকি সব (মার্কেটিং, নিরাপত্তা, ভিজিটর, অ্যাডমিন সেটিংস)।
6. আসল ডাটা `convert` → `load` → `verify`, তারপর সুইচ।

হুবহু নেওয়া যায়নি এমন কয়েকটা দ্রুত-খোঁজার index (`_plan.json` → `skipped`) MongoDB-তে কোয়েরি লেখার সময়
আলাদা করে করতে হবে। এগুলো শুধু গতির জন্য, কোনো নিয়ম না।
